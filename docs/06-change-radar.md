# ETF 目录变化雷达

变化雷达将每次采集视为一个标准化目录版本。自动任务在刷新前保留上一版 `catalog-latest.json`，刷新后比较新旧版本，并把差异转成可追溯事件。

## 追踪事件

- `product_added`：股票代码首次出现在当前目录。
- `product_removed`：股票代码从当前采集目录消失，需要复核是否下架、改名或来源失败。
- `fee_changed`：管理费或持续费用发生变化。
- `benchmark_changed`：追踪指数或比较基准变化。
- `style_changed`：主动／被动管理方式变化。
- `status_changed`：交易状态变化。
- `name_changed`：官方基金名称变化。
- `aum_jump`：相同币种下基金规模较上一版本变化至少 20%。

日常 NAV 和小幅 AUM 变化不会被记录，避免时间线被普通市场波动淹没。

## 幂等和历史保留

每个事件使用以下字段生成稳定哈希：

- 事件类型
- 股票代码
- 变更前值
- 变更后值
- 检测版本时间

新事件与历史文件合并时按哈希去重，因此同一目录版本重跑不会重复生成事件。历史最多保留 500 条，页面默认显示最近 12 条并支持分类筛选和逐步加载。

## 自动流程

1. 保存上一版标准化目录到临时文件。
2. 运行发行商发现和采集器。
3. 重建统一目录。
4. 运行 `scripts/build-change-radar.mjs`。
5. 更新最新差异文件、浏览器数据文件和去重历史。
6. 与其他数据一起提交并触发 GitHub Pages 部署。

## 失败边界

“目录消失”不直接等同于 ETF 下架。它也可能来自发行商页面改版、采集失败或代码变更，因此页面将这类事件标为高关注并保留官方来源核对入口。

## 测试

```powershell
node tests/change-radar.test.mjs
```

测试覆盖新增、消失、基准变化、费率变化、规模阈值和事件去重。
