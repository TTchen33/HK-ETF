# 自动数据更新说明

## 目标

网站部署后不依赖 Codex、开发者电脑或人工操作。GitHub Actions 会在香港工作日晚上自动执行采集器；采集器自行请求配置中的公开基金产品页、标准化资料、保存最新结果，并在数据变化时提交更新。

## 当前工作流

- 调度：每周一至周五 22:00（香港标准时间；GitHub 的计划任务使用 UTC 14:00）。
- 可手动触发：GitHub Actions 页面中的 **Run workflow**，仅用于调试或首次部署。
- 输入：Global X 的公开 sitemap 候选页，以及 `config/value-etfs.json` 中明确列出的 Value ETF 公开产品页。
- 输出：各发行商的标准化资料，以及由合并脚本产生的 `data/catalog-latest.json` 和 `data/catalog-latest.js`；前台直接读取后者。
- 原始页快照：本地运行时保留在 `data/raw-*.json`，但不提交到仓库，以免仓库膨胀或复制来源网页内容。
- 失败行为：某一页面采集失败时，流程报错；已提交的上一版标准化数据不会被覆盖。

## 为什么不采用实时数据

首版的核心是透明的 ETF 产品信息、费率、结构和官方披露的净值。公开页面上的 iNAV 是盘中估算值，发布方式会因产品而异；实时或完整历史市场数据也可能受到数据服务许可限制。因此，第一版只做每日/披露频率的官方资料同步，并把 iNAV 设计为以后可选字段。

## 上线前检查

1. 在 GitHub 仓库的 Actions 设置中允许工作流写入仓库内容。
2. 首次运行工作流，并确认 `data/catalog-latest.json` 和 `data/catalog-latest.js` 被提交。
3. 检查每条记录都有来源网址、采集时间与资料对应日期。
4. 逐一核对计划接入来源的使用条款、署名和自动访问限制。
5. 网站前台显示“资料来源、资料日期、系统更新时间”，而非声称资料实时。

## 扩展方式

每一家发行商新增一个独立采集器和配置文件；只有通过字段映射、数据校验、14 天稳定更新和来源条款核对后，才接入主网站。这样一个发行商页面改版不会影响其他来源。
